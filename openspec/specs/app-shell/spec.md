# app-shell Specification

## Purpose

Defines the cross-platform application shell for the CompPrice unit-price comparison app: the Flutter project setup, theming, and the single-screen UI structure that hosts the comparison feature.

## Requirements

### Requirement: Flutter project targets Android and iOS

The system SHALL be a Flutter (Dart) project that builds successfully for both Android and iOS from a single codebase.

The system SHALL declare no third-party package dependencies in `pubspec.yaml` beyond what the Flutter SDK provides by default.

#### Scenario: Android build succeeds

- **WHEN** a developer runs `flutter build apk` from the project root on a clean checkout with the Flutter SDK installed
- **THEN** the build completes successfully and produces an APK artifact

#### Scenario: iOS build succeeds without code signing

- **WHEN** a developer runs `flutter build ios --no-codesign` from the project root on macOS with the Flutter SDK installed
- **THEN** the build completes successfully

#### Scenario: No third-party dependencies

- **WHEN** a reviewer inspects `pubspec.yaml`
- **THEN** the `dependencies` section lists only `flutter` (and `cupertino_icons` if generated by `flutter create`) and the `dev_dependencies` section contains only what `flutter create` scaffolds

### Requirement: Material 3 theming with system light/dark mode

The system SHALL use Material Design 3 theming and SHALL set `ThemeMode.system` so the active theme follows the operating system's light/dark setting.

The system SHALL NOT hardcode raw colors for semantic UI affordances (such as the lowest-price highlight); it SHALL instead use Material 3 color roles from the active `ColorScheme` so the UI remains legible in both light and dark mode.

#### Scenario: Light mode follows OS

- **WHEN** the OS is set to light mode and the user opens the app
- **THEN** the app renders with the Material 3 light color scheme

#### Scenario: Dark mode follows OS

- **WHEN** the OS is set to dark mode and the user opens the app
- **THEN** the app renders with the Material 3 dark color scheme and the lowest-price highlight remains legible

### Requirement: Single-screen layout

The system SHALL present a single screen containing, at minimum:

- A "Price" input field (rubles, decimal).
- A "Quantity" input field (decimal).
- An "Add" action that appends the entered product to the list.
- A scrollable list of added products, each row showing the auto-generated name, the entered price and quantity, the computed unit price, the lowest-price highlight (when applicable), and a delete control.

The system SHALL NOT introduce additional screens, navigation routes, or tabs.

#### Scenario: Initial layout

- **WHEN** the user opens the app for the first time
- **THEN** the screen shows the price input, quantity input, and "Add" action, and the list area is either empty or shows a brief empty-state hint

#### Scenario: Decimal-friendly keyboard

- **WHEN** the user focuses the price or quantity input
- **THEN** the system requests a numeric keyboard that permits a decimal separator
