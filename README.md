## Что это такое?

Лёгкое offline-first мобильное приложение для моментального сравнения удельной стоимости товаров («цена за единицу/объём») во время покупок. Приложение работает автономно, не содержит рекламы, трекеров и сторонних runtime-зависимостей.

> Проект завершён как персональная утилита для ежедневного использования и решает прикладную задачу без необходимости дальнейшего расширения функционала.

## Зачем нужен этот проект

В супермаркетах производители часто маскируют рост цен нестандартными объёмами упаковки (0.85 л, 820 г, 4 шт.), из-за чего сопоставить реальную стоимость товаров «на глаз» затруднительно. Существующие решения из магазинов приложений либо перегружены рекламой и баннерами, либо требуют платную подписку и запрашивают избыточные системные разрешения (доступ в сеть, геолокацию).

Мне требовалось простое, надёжное и быстрое решение, которое я разработал за один вечер. Проект создан с фокусом на минимализм и надёжность: здесь полностью отсутствуют сторонние библиотеки (Zero External Dependencies), а требования и бизнес-логика формализованы через спецификации. Для меня как начинающего инженера это практический пример создания легковесной утилиты с детерминированной сборкой, безопасной цепочкой поставок и чистой архитектурой без оверхеда.

## Стек технологий

- **Фреймворк и язык:** Flutter, Dart 3.
- **Пользовательский интерфейс:** Material Design 3 (поддержка системных темной и светлой тем, адаптивная подсветка контрастов).
- **Управление состоянием:** In-Memory Reactive State (`StatefulWidget`, единый экран без накладных расходов на роутинг).

- **Контроль качества:** Flutter Lints, Widget & Smoke Tests.

## Быстрый запуск

## Ключевые инженерные решения

1. **Zero External Dependencies (Безопасность цепочки поставок):**  
   В `pubspec.yaml` не подключено ни одной сторонней внешней зависимости — только стандартный Flutter SDK и базовые иконки. Это исключает риски supply-chain атак (компрометация сторонних пакетов), предотвращает деградацию и конфликты версий библиотек (dependency rot) и гарантирует минимальный вес итогового бинарного файла.
2. **Defensive Input Handling и устойчивость к локалям:**  
   В мобильных ОС клавиатуры могут отдавать как точку, так и запятую в качестве десятичного разделителя. Обработка ввода реализована через кастомный `TextInputFormatter`: блокируется ввод буквенных символов и повторных разделителей, а парсер прозрачно нормализует запятую в точку. Валидация граничных условий предотвращает ошибки деления на ноль (`NaN` / `Infinity`).
3. **Сохранение математической точности для ранжирования:**  
   Округление цены за единицу товара до двух знаков после запятой (`toStringAsFixed(2)`) происходит исключительно на уровне отображения в UI. Внутри состояния сохраняется сырое значение `double`, что исключает ложные ничьи при сравнении товаров, разница в цене которых проявляется в третьем или четвёртом знаке.
4. **Контрастная адаптивность интерфейса (Material 3 Theme Aware):**  
   Индикация наиболее выгодной позиции выполнена мягкой цветовой заливкой карточки без перегрузки лишними иконками. Цветовая палитра адаптируется под системную тему оформления (светлая/тёмная), обеспечивая устойчивую читаемость текста без конфликта контрастов.

## Практика разработки и Spec-Driven Development

Проект реализован по методологии **Spec-Driven Development** с использованием спецификаций [OpenSpec](https://github.com/Fission-AI/openspec):

- **Формализация требований до кода:** архитектура и логика зафиксированы в контрактах каталога `openspec/specs/`:
  - `unit-price-compare` — математическая модель, нормализация ввода и поведение списка;
  - `app-shell` — требования к единственному экрану и системной Material 3 теме;
  - `app-branding` — нейминг и спецификация нативных иконок под разные плотности экранов.
- **Управление изменениями (Change Proposals):** визуальный рефакторинг индикатора лучшей цены (замена яркой иконки-звезды на мягкую фоновую подсветку) проводился через структурированное предложение `replace-best-product-marker` с фиксацией влияния на UX и читаемость.

## Тестирование и качество кода

В проекте используется встроенный статический анализ и тесты интерфейса:

```bash
# Запуск статического анализатора (flutter_lints)
flutter analyze

# Запуск смоук- и виджет-тестов
flutter test
```

- Правила линтинга определены в [analysis_options.yaml](analysis_options.yaml) (`flutter_lints`).
- В [test/widget_test.dart](test/widget_test.dart) зафиксированы базовые сценарии: рендеринг компонентов, добавление позиций, проверка вычислений и удаление элементов из списка.
